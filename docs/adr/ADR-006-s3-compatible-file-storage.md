# ADR-006: S3-Compatible Object Storage with MinIO

## Status
Accepted

## Context
Schools accumulate substantial unstructured binary files: student admission identity scans, birth certificates, medical forms, report card PDFs, profile photos, and circular attachments. Storing binary blobs directly in PostgreSQL degrades relational table scan speeds, inflates database backup sizes, and exhausts database connection bandwidth.

## Decision
We established an **S3-Compatible Object Storage** strategy using **MinIO**:
1. All binary files are stored in MinIO buckets (`school-documents`, `school-photos`, `school-reports`).
2. PostgreSQL only stores metadata records (`file_metadata` table: bucket, object key, MIME type, size, uploader).
3. Access is strictly controlled via signed URLs generated by the API backend.

## Consequences
### Positive
- Lean PostgreSQL database backups and high database query performance.
- Full compatibility with AWS S3, Cloudflare R2, or self-hosted MinIO VPS setups.
- Streaming uploads directly from client to storage via presigned tickets reduces server RAM usage.

### Negative
- Requires maintaining bucket access policies and presigned token expiration handling.
